# Аудит исходного прототипа

## Текущее состояние

- Репозиторий содержит статический сайт в `public_html/`: один `index.html`, три CSS-файла и vanilla JavaScript.
- Визуальная система уже сформирована: тёмный фон, cyan/magenta акценты, Inter/Russo One, карточки, сетка, адаптивные состояния и простые анимации.
- Каталог формируется в браузере из `catalog-data.js`; источник данных и ссылки привязаны к Ozon.
- Товары группируются регулярными выражениями по модели автомобиля. Отдельных URL разделов и карточек нет.
- Изображения товаров лежат локально, изображения лендинга загружаются с внешнего Bitrix24 CDN.
- Форма заявки является заглушкой: серверной отправки, валидации и хранения нет.
- PHP, Bitrix-шаблон, инфоблоки, checkout, доставка и уведомления отсутствуют.
- GitHub Actions публикует `public_html` как статический GitHub Pages-сайт.

## Что переиспользуется

- `style.css`, `products.css`, `hero-title.css` и существующие изображения;
- header/footer, hero, преимущества, портфолио, применение и FAQ;
- сетка и визуальный язык карточек товаров;
- мобильная навигация и фотогалерея как UI-паттерны.

## Что мешало переносу на Bitrix

- товарные данные и цены полностью захардкожены в JavaScript;
- статические карточки продублированы в HTML и затем заменяются JavaScript;
- нет серверного источника истины для цены;
- нет SEF-маршрутов каталога;
- отсутствует разделение presentation/business/infrastructure;
- форма не защищена CSRF и не взаимодействует с сервером.

## Риски и долги

- Лендинг зависит от внешних изображений Bitrix24 CDN и Google Fonts.
- В игнорируемом локальном `.vscode/sftp.json` хранятся FTP-реквизиты открытым текстом. Файл не отслеживается Git, однако пароль необходимо сменить и перенести в менеджер секретов.
- Без установленного Bitrix локально возможны только статический анализ и PHP lint; интеграционная проверка инфоблоков выполняется на стенде.
- Статический `index.html` сохранён для GitHub Pages. На Bitrix-хостинге веб-сервер должен отдавать `index.php` раньше `index.html`.

## Архитектура MVP

- Товары и разделы: штатный инфоблок Bitrix.
- Заказы: отдельный инфоблок, без модулей `sale` и `catalog`.
- Представление: шаблон `local/templates/darkstyle` и компоненты `darkstyle:catalog`, `darkstyle:checkout`.
- Бизнес-логика: PHP-классы `DarkStyle\Catalog`, `DarkStyle\Order`, `DarkStyle\Delivery`, `DarkStyle\Notification`.
- Интеграции: провайдеры доставки за единым контрактом; до выдачи credentials работают прозрачные fallback-тарифы.
- Настройки: Bitrix options, переменные окружения либо игнорируемый `config.local.php`.
- Инициализация: одноразовый admin-only скрипт создаёт тип инфоблоков, инфоблоки и свойства.

## План первой итерации

1. Подключить существующий дизайн как Bitrix-шаблон.
2. Добавить инфоблочный каталог с маршрутами списка, раздела и товара.
3. Реализовать модальный checkout одного товара и защищённый AJAX.
4. Пересчитывать товар, доставку и итог только на сервере, сохранять заказ в инфоблок.
5. Отправлять менеджеру почтовое уведомление через абстракцию notifier.
6. Добавить СДЭК и Почту России через общий контракт с fallback до настройки API.
7. Проверить синтаксис, безопасность и описать установку.
